# MOISE — agent edition of the paper

An AI-readable restatement of

> Argov, E., Barnea, E., Binyamini, A., Borenstein, E., Elkayam, D. & Rozenshtrom, I. (2012).
> *MOISE: A DSGE Model for the Israeli Economy.* Bank of Israel Research Department, Discussion Paper 2012.06.
> [PDF](https://boi.org.il/media/ybvpydng/dp12065e.pdf)

PDFs are a bad input for code-writing agents: the text layer drops hats, mangles subscripts and
turns Greek letters into junk. This folder holds the paper's mathematical content as clean
Markdown + LaTeX, every table as CSV, and the impulse-response charts as data, so agents and
people can work without opening the PDF.

**It is not a substitute for the paper.** Equations, numbers and notation are transcribed;
explanations are short paraphrases. Read the original for the authors' reasoning. This project is
not affiliated with or endorsed by the Bank of Israel.

## Verification status

- **Source:** every page was read from 300-DPI images, zooming to 600–3000 DPI where needed — never
  from the PDF's text layer.
- **Two independent passes per section.** Each of the 13 parts was transcribed by one AI agent and
  then checked by a second agent that had not seen the work. The checker rendered the transcription
  with pdflatex in the paper's own font and compared it with the original page symbol by symbol;
  several checkers also compared glyph positions read from the PDF's embedded fonts.
- **Tables:** every number was cross-checked against the PDF text layer and glyph coordinates;
  Table 7's 750 cells were checked three independent ways.
- **Outcome:** 331/331 numbered equations, 25 unnumbered displays and 148 inline definitions
  (504 math blocks); every block compiles. The checks found **one** transcription error in the math
  (equation 280, a hat position), now corrected, and about 40 explanatory lines that were reworded
  or corrected. 117 `Note:` lines record places where the paper itself looks wrong or inconsistent —
  always transcribed **as printed**. No glyph is left marked uncertain.
- **Charts:** the impulse responses (Figures 6–18, 156 panels) were extracted from the PDF's vector
  graphics and validated by re-plotting and an independent raster cross-check (`data/irf/README.md`).

All of this is **machine verification**. Human verification of each equation is tracked in
`model/moise.yaml` (`verified: true`) and `docs/verification-log.md`, not here.

## How to use this folder (agents: read this first)

1. **`00-overview.md`** — what the model is, its structure, and a map of every section to its
   printed and PDF page and to the file here that covers it.
2. **`01-notation.md`** — every symbol: LaTeX form, meaning, kind (variable / parameter / shock /
   steady-state value), where it is first used, and the **code name** used in code forms.
3. **To implement the model:** `10-log-linear-model.md` (Appendix D) is the system the solver
   needs — equations (212)–(331), each with a plain code form. Steady-state values that appear as
   coefficients come from `09-steady-state.md`. Parameter values are in `data/table1_calibrated.csv`,
   `data/calibration_in_text.csv` (values stated only in the text) and the posterior tables
   `data/table2_*.csv`–`data/table4_*.csv`.
4. **To understand the economics:** `02`–`04` (the non-linear model, Section 3) and `05` (data,
   detrending and measurement).
5. **For replication tests:** `08-model-properties.md`, `data/table7_variance_decomposition.csv`,
   `data/table6_moments.csv` and the digitized impulse responses in `data/irf/`.
6. **Machine-readable:** `equations.json` has one record per math block (id, kind, section, pages,
   title, LaTeX, code form).
7. **Everything in one file:** `MOISE_agent_edition.md` (generated by concatenating 00–10).

**Precedence when representations disagree:** the PDF beats the LaTeX, and the LaTeX beats the
code form. If you find a disagreement, report it — do not silently pick one.

## Conventions

### Math blocks

```
<!-- kind: eq; id: 229; section: D.4; page: 114; pdf_page: 120 -->
**(229) Phillips curve of foreign intermediate-goods firms (in local currency)**

$$
… LaTeX …
\tag{229}
$$

Meaning: one-line paraphrase.
```

- `kind`: `eq` = numbered display (id = the paper's number); `display` = unnumbered display,
  id `N.uK` = the K-th unnumbered display after equation (N); `inline` = math from running text
  or a footnote that defines something, id `N.iK`.
- `page` = printed page number; `pdf_page` = page in the PDF file (= printed + 6).
- `Note:` lines record suspected misprints in the paper (transcribed as printed).

### LaTeX

- Symbols, sub/superscripts, signs, bracket types and term order exactly as printed; nothing is
  simplified, reordered or corrected.
- Sub/superscripts are always braced; subscript before superscript (`\pi_{y,t}^{*}`).
- `\hat{x}` is a single-letter hat, `\widehat{mc}` a wide one; stacked accents nest outside-in
  (`\hat{\bar{\pi}}` = hat printed over a bar).
- Accent *width* is not preserved for single symbols: a full-width bar or tilde over one letter is
  written `\bar{…}` / `\tilde{…}`.
- Only `amsmath`/`amssymb`; every block compiles with pdflatex.

### Code forms (Appendix D)

Generated mechanically from the LaTeX by a strict converter (`tools/paper/latex2code.py`):

- each symbol becomes its code name from `01-notation.md` / `data/notation_codes.csv`
  (the key is the LaTeX symbol without its time index);
- `x_{t}` → `x`, `x_{t+1}` → `x(+1)`, `x_{t-1}` → `x(-1)`; `E_{t}` is dropped (Dynare convention);
- explicit `*`, `/`, `^`; all brackets become `( )`;
- in Appendix D a hat marks a log deviation; a symbol with the same letters but no hat and no time
  index is a steady-state value (`_ss`); `*` marks foreign (`_star`);
- printed variants of a standard symbol (a lower-case subscript, a missing comma, a stray letter)
  share the standard code name; every such mapping and its reason is in `data/notation_aliases.csv`.

`python tools/paper/check_paper.py` verifies that every code form still matches its LaTeX.

Implementers must decide how to handle these — do not assume the printed form is what the Bank

### Notation the code forms keep separate

The paper sometimes writes a variable with and without its hat. The code forms keep both names so
nothing is merged silently; all three pairs are almost certainly the same variable:
`pibar` / `pibar_nohat` (e.g. (259), (298)–(306)), `pibar_star` / `pibar_star_nohat`
((287), (300), (318)), `s_Bstar` / `s_Bstar_nohat` ((272)). `dS` (model depreciation in (259)) and
`Delta_S` (observed depreciation in (306)) are different objects.

### Parameters

- $\gamma_{B}$ prior: the text gives mean 0.1, Table 2 prints 0.01. Figure 3's prior curve is
  hump-shaped with mode ≈ 0.0073, which fits gamma(mean 0.01, std ≈ 0.005); the printed std "0.01"
  is most likely 0.005 rounded. Do not use gamma(0.01, 0.01).
- Prior cells printed "0.00" (8 standard deviations, 6 means) are roundings, not values. "Inf" is
  printed as text and is not defined.
- Labels differ between tables and equations: $\rho_{\varphi^{H}}$ (Table 2) vs $\rho_{H}$ (4.4.2,
  Table 5); $\chi_{E}$, $\xi_{E}$ (tables) vs $\chi_{EM}$, $\xi_{EM}$ ((95)). $\rho_{DRP}$,
  $\rho_{WT^{*}}$ and $\rho_{OIL}$ are listed but no estimate is reported.

### Results

- Text vs figures: the figures show higher export peaks than the text states (Figure 7: 0.79 vs
  "about 0.5"; Figure 9: 2.84 vs "about 2") and a lower interest-rate peak in Figure 7 (0.85 vs 1.0).
- Only 13 of the 25 shocks have impulse responses in the paper (Figures 6–18).
- The figures do not say which gray band is 70% and which 90%; the inner (darker) band is taken
  as 70% because it nests inside the other.

### Section 3 (non-linear model)

Printed inconsistencies, all noted under the equations: (4) $\Gamma_{B^{*}}$ without $t$;
(15) $\Lambda_{t+k}$ without $h$; (16) $W_{h,t-1}$; (29), (34), (51) subscripts on the inflation
objective; (32) time subscripts inside the sum; (35) exponent $\mu_{C}/\mu_{C-1}$; (48), (50)
discount-factor indices; the definition after (50); (85)–(86) $\epsilon^{IM}$ vs $\varepsilon^{IM}$
in (38); (89) a stray $t$.

## Correcting this edition

Use the tools in `tools/paper/` (see its README): fix the LaTeX, add any new symbol to
`data/notation_codes.csv`, then run `python tools/paper/check_paper.py --fix-code --write-json`
and `python tools/paper/check_paper.py --compile`. Log every change in `docs/verification-log.md`.
